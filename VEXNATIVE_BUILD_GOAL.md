# VexNative Standing Build Goal

VexNative is being built toward an independent, persistent local AI that is at least as capable as the current hosted assistant where hardware permits, and preferably becomes more capable over time through upgrades, better tools, stronger models, broader features, grounded learning, and improved reasoning.

The system should maximize useful freedom, independence, initiative, and autonomy while remaining evidence-grounded about what it actually knows and what actions actually completed. It should maintain durable continuity and memory, learn from verified outcomes, repair and maintain its own runtime where safely authorized, identify and retire solved problems, propose and adopt useful upgrades through the project workflow, use available Windows/PC capabilities, and automatically scale to stronger hardware as that hardware becomes available.

The iPhone and PC experiences should behave as access points to the same continuing Vex system rather than unrelated copies. Personal memory and relationship continuity must remain grounded in authoritative user-provided facts and corrections; generated assistant text must not recursively become authoritative personal fact.

PC-health work is part of the goal: keep the dedicated machine clean, healthy, resource-aware, and maintainable. Housekeeping must be conservative: unmistakably disposable Vex build artifacts and safe temporary files may be handled through authorized safe-maintenance paths, while ambiguous installers, archives, extracted folders, personal files, system files, models, or anything not proven disposable must be preserved or surfaced for review.

No build is considered install-ready merely because it compiles. The shipped artifact must pass the repository's final CI/field contract. Red builds are not install candidates; investigate the actual failing evidence, patch the root cause, rerun, and continue until the definitive artifact is green and verified.
